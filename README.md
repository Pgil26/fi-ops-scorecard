# FI Ops Scorecard (Floral Image)

Executive FI Ops board exported from Grok Build: Salesforce (units on hire, closed won, open trials, at-risk), RouteMap changeovers, and Geotab van activity, with a location filter. The numbers are baked into the page (`src/data/ops.ts`), so no login is needed.

**Public URL:** https://pgil26.github.io/fi-ops-scorecard/

## Structure
- `src/` — TanStack Start + React app (`src/routes/index.tsx` → `src/components/ops-board.tsx`, data in `src/data/ops.ts`).
- `docs/` — static build served by GitHub Pages (`main` branch, `/docs` folder). Generated by `scripts/publish-pages.sh`; do not edit by hand.
- `.vercel/`, `vercel.json` — original Grok Build / Vercel deploy output.

## Publishing to GitHub Pages
One command rebuilds `docs/`:

```bash
./scripts/publish-pages.sh
git add -A docs && git commit -m "Refresh FI Ops scorecard" && git push origin main
```

To refresh the numbers, update `src/data/ops.ts` first, then run the above.

What the script does: installs dependencies if needed, builds with `PAGES_BASE=/fi-ops-scorecard/` (which makes `vite.config.ts` use that base, prerender `/` to static HTML, and write to `dist/` instead of the committed `.vercel/output`), replaces `docs/` with the static output (keeping `docs/.nojekyll`), points favicon / `/__grok/*` links at `/fi-ops-scorecard/`, writes a static web manifest, and fails if `docs/index.html` references any local path outside the base or any missing file.

Normal `npm run build` (Vercel) is unchanged: base `/`, no prerender.

### Daily step (weekday digest routine, after ops.ts is rebuilt and before publish-pages.sh)
```bash
DAY=2026-11-26                          # coverage day
RAW=/workspace/fi_digest/$DAY/raw
python3 scripts/fi-ops/board_extras.py queries --day $DAY   # prints 6 SOQL queries
# run each with user-salesforce-reads soqlQuery (write_to_file) and save the result as $RAW/act_<name>.txt (or .json):
#   act_trials, act_refresh, act_fu_due, act_moves, act_overdue, act_won
python3 scripts/fi-ops/board_extras.py activity --day $DAY --raw $RAW
python3 scripts/fi-ops/board_extras.py fleet --day $DAY     # reads /workspace/geotab-daily-start-end-local-*.csv
```
Any missing `act_*` file marks the report card **pending** (no older day is reused). `activity` reads units on hire from `ops.ts`, so run it after the ops.ts rewrite.

### Monthly step (first weekday of the month, or on request): data for the Units on Hire by Location Page
```bash
python3 scripts/fi-ops/board_extras.py uoh-query            # first page; then --after <last Id> for each next page
# save each 2,000-row page as /workspace/fi_digest/uoh_history/<pull-date>/pNN.json (about 16 pages)
python3 scripts/fi-ops/board_extras.py uoh --raw /workspace/fi_digest/uoh_history/<pull-date> --pulled <pull-date>
```
This writes `/workspace/fi_digest/uoh_history/<pull-date>/uoh_page_data.json` only — it does not change the scorecard and needs no rebuild. **Then update the Page** (canvas `daf6a31b-59bd-4a5b-88f5-cab878736e23`, https://cursor.com/canvas/store-e6ec9570-2655-4b1d-bf99-ed134ad325f4/daf6a31b-59bd-4a5b-88f5-cab878736e23) with ReadCanvas + EditCanvas/WriteCanvas: replace the `SM` and `YE` arrays and the totals table in the sections "SINGLE-UNIT VS MULTI-UNIT ACCOUNTS · CURRENT BOOK" and "UNITS ON HIRE SINCE 2013 · YEAR-END SNAPSHOTS INCL. CLOSED ACCOUNTS", plus the pull date and any numbers quoted in their text. Leave the Page's other sections alone. Prices use row-level `convertCurrency(UnitPrice)`, never SOQL SUM aggregates. São Paulo excluded.
